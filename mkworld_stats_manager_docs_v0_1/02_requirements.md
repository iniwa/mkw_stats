# MKWorld Stats Manager 要件定義 v0.1

## 1. 機能要件

### 1.1 VR記録

公式オンライン野良マッチのVRを記録する。

前提:

- API取得は不可
- 手入力
- 複数VRアカウント対応
- 使用アカウントは設定画面で選択

記録項目:

| 項目 | 必須 | 備考 |
|---|---:|---|
| VRアカウント | 必須 | 設定画面で選択中のアカウント |
| コース / 道中コース | 必須 | コース決定時に入力 |
| 参加人数 | 必須 | 12 / 24など |
| 順位帯 | 必須 | 上位 / 中位 / 下位 |
| VR増減 | 必須 | +48, -32など |
| VR before | 任意 | 自動計算可能 |
| VR after | 任意 | 自動計算可能 |
| キャラ | 任意 | 前回値を引き継ぐ |
| マシン | 任意 | 前回値を引き継ぐ |
| メモ | 任意 | レース単位メモ |

### 1.2 順位帯

| 人数 | 上位 | 中位 | 下位 |
|---:|---|---|---|
| 12人 | 1〜4位 | 5〜8位 | 9〜12位 |
| 24人 | 1〜8位 | 9〜16位 | 17〜24位 |

### 1.3 VR計算

VRはアカウントごとに管理する。

```text
次のVR = 前回VR + VR増減
```

手動補正も可能にする。

## 2. Lounge要件

### 2.1 Lounge API同期

API同期対象:

- Table ID
- プレイ日時
- フォーマット
- 参加人数
- スコア
- MMR増減
- Tier
- プレイヤー情報

Lounge APIではレース単位の詳細コース情報は取得できない前提とする。

### 2.2 更新方式

#### 手動更新

「更新」ボタンを押した時にAPI同期する。

#### 継続更新

- 3分ごとに更新
- マッチ終了後の利用を想定
- 停止条件:
  - 新規TableまたはMMR更新を検知
  - 1時間更新なし
  - 手動停止
  - APIエラー連続

### 2.3 Lounge中コース履歴

- 1マッチ12レース
- Race X / 12 を表示
- 走ったコースを履歴管理
- リピック警告を出す
- 12人で道中コースを選んだ場合に警告
- 12レース目で自動マッチ終了
- 手動マッチ終了も可能
- 警告は出すが記録可能

## 3. プレイ中UI要件

野良VRとLoungeで大きく画面を分けない。

共通フロー:

```text
コース選択
  ↓
コース確認
  ↓
メモ表示
  ↓
レース
  ↓
結果または記録入力
  ↓
次のコース選択
```

## 4. コース選択要件

- 全体マップ上の地点クリックで選択
- 出発地点 → 到着地点
- 同地点2回クリックで3周コース
- 異地点クリックで道中コース
- 確定前に確認ダイアログを出す
- 補助検索も用意する
- 自然言語検索は不要

## 5. コースメモ要件

- 付箋型メモ
- 複数メモ作成可能
- 優先度設定
- タグ設定
- スクロールで全メモ確認
- マップ上ピンに関連付け可能
- ピンホバーでメモ表示

## 6. 画像要件

- コースメモ画像
- ショートカット補助画像
- ルート図
- リザルトスクリーンショットは不要
- 画像アップロードは任意
- 画像エンコードはPC側で事前に行う運用
- Raspberry Pi側で重いエンコードはしない

## 7. キャラ/マシン要件

- マシン性能は Mario Kart Blog のマシン性能ページを参考元候補とする
- 自然言語検索は不要
- 数値条件・チェックボックス・ソート条件で検索
- 現在構成との差分比較を行う

## 8. アイテムテーブル要件

- Mario Kart Blog を参考元候補とする
- game_versionを管理
- 正確な確率が不明な場合は参考テーブルとして扱う
