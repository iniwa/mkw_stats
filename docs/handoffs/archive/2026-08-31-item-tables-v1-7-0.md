# Item table refresh for v1.7.0

Status: complete; implementation, focused verification, and primary review finished on 2026-08-31. Initial route: `bounded`. No production deployment requested or performed.

## Goal and approved scope

The user approved reflecting the previously retrieved v1.7.0 item tables in the app. Update every live item-table display: the Items view and the Playing assist preview. This is a frontend-only reference-data update; deployment, commit, and push are not requested.

## Sources and known data

- Source: https://japan-mk.blog.jp/mkworld.item-1
- Source revision: 2026-07-04; retrieved and visually inspected on 2026-08-31.
- Game version: v1.7.0, released in Japan on 2026-07-01.
- Each time-specific table contains both 12-player and 24-player rank rows.
- Start to approximately 21 seconds: https://livedoor.blogimg.jp/nim_2525/imgs/c/3/c3999c26-s.png
- Approximately 21 to 26 seconds: https://livedoor.blogimg.jp/nim_2525/imgs/5/0/5057927c-s.png

- Conditional extras: https://livedoor.blogimg.jp/nim_2525/imgs/9/1/914af419-s.png (identical to the existing extra PNG).
- These are community observations, not official probability percentages. Exact probabilities and distance thresholds remain unconfirmed. Transition times are approximate. The source reports Golden Dash Mushroom from about 30 seconds, Lightning from about 40 seconds, and Kamek/Spiny Shell initial availability still under investigation.

## Required behavior

1. Items retains its existing navigation and four readable sections: `開始〜約21秒`, `約21〜26秒`, `約26秒以降`, and `追加出現アイテム`.
2. Clearly show v1.7.0, source revision 2026-07-04, the source link, and that the tables contain both 12-player and 24-player ranks. Keep concise approximate-time and uncertainty notes; the late table must not imply every item unlocks at 26 seconds.
3. Playing uses the same new phase assets, with an accessible manual phase selector. Default to the normal `約26秒以降` table. Keep the existing participant/source context and ranked approximation warning. Selecting a phase must not submit a form or affect session/race state. No automatic timer or inferred live race time.
4. Use the existing UI styles where possible. All PNGs load locally. A tiny shared static definition is appropriate for the two consumers; do not add a generic subsystem.
5. Add three new versioned, phase-specific PNG filenames under `frontend/public/assets/items/`; reuse the unchanged `item-table-extra.png`. Retain the old 12p/24p PNGs as unreferenced historical assets for this small update, but no live JSX may use them. New versioned paths avoid stale browser caches.
6. Keep image loading fallback on Items and avoid horizontal page overflow at 375px.
